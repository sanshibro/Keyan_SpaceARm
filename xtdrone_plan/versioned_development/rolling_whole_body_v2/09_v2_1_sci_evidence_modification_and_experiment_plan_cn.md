## 1. 总体目标和不变边界

本轮开发不推翻 Rolling-WB-V2 的论文主线，也不修改或覆盖已经冻结的 90 对场景、450 次闭环结果。V2.1 只处理当前证据链中的四个高风险问题：

1. 定位并降低闭环执行 jerk；
2. 将滚动窗口接管由位置连续补强为全身状态及一阶导数连续；
3. 补齐每任务累计计算预算、重规划和安全缓存时间证据；
4. 验证 COM、推力比和倾角等飞行负担代理与 PX4 闭环量的对应关系。

以下内容保持不变：

- 输入仍为状态估计辅助的 RGB-D/SLAM 冻结地图，不允许规划器访问真值障碍；
- 全身状态仍包含 UAV 位置、偏航、连续体弯曲角、弯曲平面和时间；
- 保留风险感知离散种子、有限预算连续细化、独立密集验证、安全轨迹缓存和滚动更新；
- 保持机体/机械臂包络、未知空间、安全净空、速度、加速度、jerk、形态速率、推力和倾角硬约束；
- 保持五种方法的名称、来源说明和失败定义；
- 不删除不利指标，不排除起停或切换附近样本，不按方法改变 jerk 滤波参数；
- 不以降低速度或延长任务时间作为唯一的 jerk 改善手段。

现有冻结结果定位为先导主实验。V2.1 修改完成后使用新种子生成最终论文实验，旧结果不与新算法结果混合冒充同一版本。

### E3 续跑调度审计（2026-08-03）

E3 运行中发现，原弹性监督器在系统级中断后会从预注册列表第 1 个场景重新调用场景级流水线。虽然已有方法结果不会被重跑，但冻结地图加载、单场景聚合与资格检查会被反复执行，造成大量无效墙钟时间。该问题只属于实验编排层，不属于任一规划方法失败。

后续采用“按冻结预注册清单直接续跑”策略：

1. 仅当某场景已有五个非 `SYSTEM_ERROR` 结果时快速跳过；方法失败仍是正式结果，不得重跑或删除。
2. 对缺失或仅有 `SYSTEM_ERROR` 的方法，调用原冻结单场景流水线，保持地图、方法顺序、15 s 单次规划截止期、60 s 预检与 600 s 任务时限不变。
3. 旧 `SYSTEM_ERROR` 文件原样保留作为基础设施审计证据，不计入方法成功率。
4. 仅对明确的 Linux OOM exit 137 启用已做逐数组/哈希等价验证的有界内存地图并集，其后仍通过原 schema-v5 独立审计；所有恢复记录保留。
5. 该修改不变更算法、baseline、场景、地图阈值、失败定义或指标，因而不改变 E3 的预注册比较语义。

## 3. 全状态接管定义

使用弯曲向量消除弯曲角接近零时弯曲平面角不适定的问题：

\[
\boldsymbol b=[\theta\cos\phi,\theta\sin\phi]^{\mathsf T}.
\]

定义接管状态和一阶导数：

\[
\boldsymbol q=[\boldsymbol p^{\mathsf T},\psi,\boldsymbol b^{\mathsf T}]^{\mathsf T},
\qquad
\dot{\boldsymbol q}=[\boldsymbol v^{\mathsf T},\dot\psi,\dot{\boldsymbol b}^{\mathsf T}]^{\mathsf T}.
\]

新窗口的匹配相位由下式选择：

\[
t_s^*=\arg\min_{t\in\mathcal I}
\left(
\|\boldsymbol q_n(t)-\boldsymbol q_d^-\|_{W_q}^2+
\|\dot{\boldsymbol q}_n(t)-\dot{\boldsymbol q}_d^-\|_{W_v}^2
\right),
\]

其中候选区间 \(\mathcal I\) 仍受最大前向弧长限制。接管必须同时满足冻结阈值：

\[
|\Delta\boldsymbol p|\le\epsilon_p,\quad
|\Delta\psi|\le\epsilon_\psi,\quad
|\Delta\boldsymbol b|\le\epsilon_b,\quad
|\Delta\dot{\boldsymbol q}|\le\epsilon_v.
\]

加速度差 \(\Delta\ddot{\boldsymbol q}\) 首先作为软代价和审计指标。若小样本表明仍产生明显脉冲，再提升为接管门控。直接匹配失败时继续执行旧安全轨迹并重新规划；短桥接轨迹只有在能够接受同一独立密集验证后才允许加入。

## 4. Jerk 诊断和修改规则

主指标保持现有定义：将 executor 实际下发速度统一重采样到 20 Hz，使用冻结的 Savitzky--Golay 微分参数计算平移 jerk 平方积分，并按实际命令路径长度归一化。

对每条成功轨迹将总 jerk 分解为：

\[
J_{\mathrm{total}}=
J_{\mathrm{start}}+
J_{\mathrm{interior}}+
J_{\mathrm{switch}}+
J_{\mathrm{stop}}.
\]

实施顺序：

1. 先用现有日志和新增小样本确认四项占比；
2. 若接管占主导，优先调整全状态边界与切换相位；
3. 若起停占主导，采用受速度、加速度和 jerk 约束的自适应相位渐变；
4. 若窗口内部占主导，修改连续优化中的时间参数化 jerk 代价；
5. 每次修改同时检查任务时间、规划延迟、净空和成功率，禁止只优化单指标。

V2.1 小样本目标：归一化 jerk 中位数相对冻结 V2 下降至少 40%，优选不高于 0.20；所有峰值仍满足原硬约束，成功率、净空和规划截止期不得因平滑化明显恶化。

## 5. 计算预算与安全缓存证据

每条任务新增记录：

- 规划调用次数、成功候选数、验证拒绝数和修复次数；
- 每次 seed、solve、validate、switch 的墙钟耗时；
- 单次规划 P50/P95/max；
- 每任务累计规划与验证时间；
- 单位任务时间和单位航程计算量；
- 每次候选生成时旧安全轨迹的剩余可执行时间；
- 等待、悬停、拒绝、恢复和 deadline miss 次数。

每次滚动更新必须满足：

\[
T_{\mathrm{safe,remain}}>
T_{\mathrm{plan}}+T_{\mathrm{validate}}+T_{\mathrm{switch}}+T_{\mathrm{margin}}.
\]

公平性不要求所有方法具有相同重规划次数；统一的是地图、控制器、安全阈值、任务总时限、单次截止期、失败定义和计算硬件。论文同时公开单次延迟与累计计算量，并增加累计计算预算敏感性分析。

## 6. 动力学代理对应验证

规划量：

\[
d_{\mathrm{com}},\quad\tau_g,\quad r_T,\quad\gamma.
\]

闭环记录量：

- PX4 roll/pitch、角速度和姿态误差；
- 世界系速度、加速度和位置跟踪误差；
- 总推力指令或归一化推力；
- 可获取时记录单电机最大利用率和饱和事件；
- 同步的 \(\theta,\phi\) 及弯曲向量。

报告代理与闭环量的 Spearman 相关系数、置信区间、偏差/RMSE 和安全包络覆盖率。如果相关性不足，论文统一使用“飞行负担代理”措辞，不宣称完整动力学预测或严格动力学可行保证。

## 8. 阶段验收门槛

| 类别 | 最低验收条件 |
|---|---|
| 数据完整性 | 所有轨迹、切换、规划、验证和 PX4 状态具有统一时间戳与轨迹 ID |
| 接管 | 不发生超过冻结全状态/速度阈值的强制接管；报告 max 与 P95 |
| Jerk | V2.1 相比冻结 V2 配对中位数下降至少 40%，且无硬约束违约 |
| 成功率 | 小样本无系统性退化；正式集相对最强 baseline 保持显著优势，不强求 90/90 |
| 规划 | P95 不超过 5 s，deadline miss 为 0 |
| 安全缓存 | 每次更新均满足安全剩余时间不等式，或被安全拒绝且保留旧轨迹 |
| 净空 | 在线验证和隐藏真值审计均无碰撞，硬净空阈值不放宽 |
| 动力学证据 | 代理与闭环实际量均有同步数据、相关性和误差区间；无推力饱和事件 |
| 公平性 | manifest 记录相同环境、任务预算、安全阈值和失败语义 |
| 统计 | success 使用 Wilson/McNemar；共同成功连续指标使用 Friedman 与 Wilcoxon-Holm；另报各方法自身成功集合 |

所有仿真图使用 `Closed-loop simulated` 或 `Executed simulated state`，不把仿真命令/状态无说明写成 `Measured`。论文使用 `online rolling planning`、`deadline-aware replanning` 和“在给定模型与采样假设下经独立数值验证”，不写高频 MPC、全局最优或无条件安全保证。
